# Feature: bun-to-go-migration

## Objective
Remove Bun as a runtime dependency of the services. The worker and the service-control helper become Go, so the runtime image ships Go binaries only. Bun stays only as the build tool for `apps/ui`.

## Problem (audit evidence)
- `apps/worker` (1466 src / 1014 test LOC) and `apps/control` (1091 src / 436 test LOC) run under Bun (`compose.yaml:161,200`, `infra/compose/Dockerfile.runtime` uses `oven/bun:1.3.14-alpine`).
- The worker imports `@proxycore/{certificates,config,crypto,db,domain,renderers}`. The live surface of `packages/db` is `sqlite-foundation` open, job-store, revision-store, secret-store, job-wakeup (`apps/worker/src/sqlite-runtime.ts:4-12`, `poller.ts:6`, `apply.ts:10`, `render.ts:21`).
- About 82% of `packages/db` (13,381 of 16,343 LOC) is `*.bun.ts` fixtures used only by Go interop tests. 73 Go files under `apps/api` reference bun or `packages/db` (about 25 are `configuration/sqlite_worker_*_test.go`).
- No Go version exists for: nginx/CoreDNS renderers, the worker job state machine (`transitionJob`), apply flow, certificate and basic-auth materialization, `redactSecrets`, cluster crypto, or the control helper.
- `bun:sqlite` is used in `sqlite-runtime.ts:1`, `sqlite-job-detection.ts:1`, `sqlite-job-detection.bun.ts:2`.
- `scripts/install.sh:544-547` blocks 32-bit ARM because of the Bun worker (asserted in `install.test.sh:562`). CI installs Bun in three jobs because Go tests shell out to it (`.github/workflows/ci.yml:26,49,52,122`; `release.yml:59-74`).
- `apps/ui` imports nothing from `packages/*`, so deleting them does not break the UI build.

## Why
Single static runtime, smaller images on ~1 GB hosts, no Bun/Go interop test layer, and 32-bit ARM support (DEC-051 chose Bun for build cost, DEC-052 already made Go the sole SQLite owner).

## Out of scope
- `apps/ui` stays TypeScript. It is built with Bun/Vite.
- Behavior changes to the worker or control protocols. The Unix-socket protocol and job semantics stay identical so mixed deployments keep working.
- Overlap between TS and Go was inferred from file names by the explorer. Each task confirms it before porting.

## Constraints
- English for code, comments, tests and commits. Conventional commits, no AI attribution lines (user rule). One writer at a time.
- Advisory ~400 authored changed lines per task. Test-first when a runnable deterministic test exists (`go test -short`). Port TS tests as the executable spec for each Go package.
- Do not add dependencies without asking (Docker SDK for Go is expected in T4 and needs approval).
- Worker and control wire behavior must stay byte-compatible with the TS implementation until T5 cuts over.

## Progress
T1 done. Known deviations from TS (documented, not behavior-changing for validated input): (1) `ACMEUpstream` empty string means default (TS only defaults on undefined); (2) `domain.ValidateProxySettings` takes no HTTP/3 capabilities, so the renderer checks the `http3` flag itself and passes the domain validator a copy without it, which changes only which error wins when several apply; (3) `localeCompare` is an ASCII approximation of ICU collation; (4) the sort tie-break on MX/SRV values uses Go's sorted JSON key order instead of JS insertion order.

Earlier: document created from the explorer audit. Branch not created yet: `main` has uncommitted doc edits (README, docs/*) unrelated to this feature, so the feature branch is created before T1 without touching them.
