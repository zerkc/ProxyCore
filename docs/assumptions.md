# ProxyCore Implementation Assumptions

This file records implementation choices that are not fully specified by the
MVP contracts. They are intentionally reversible. A correction should update
the affected code, tests, OpenSpec artifact, and (when the security or product
boundary changes) `docs/decision-log.md`.

| ID | Status | Choice | Reason | Impact | Verification / correction path |
| --- | --- | --- | --- | --- | --- |
| ASM-001 | accepted | Use Vitest with TypeScript scripts for unit and application tests. | The contracts require TDD but do not name a runner. | Adds a development-only test tool and standardizes `pnpm test`. | Replace the runner in `package.json`, `openspec/config.yaml`, and CI scripts if preferred. |
| ASM-002 | accepted | Use a pnpm workspace with `apps/`, `packages/`, and `services/` boundaries. | The MVP contains web, worker, helper, renderers, and shared domain code. | Keeps privileged code out of the web package and allows focused commits. | Typecheck package boundaries and remove a package only with its tests and imports. |
| ASM-003 | accepted | Use REST-style Next.js App Router route handlers for the control-plane API. | The documents define observable actions but no wire contract. | API paths and JSON payloads become the initial public application contract. | Contract tests cover each handler; a later RPC/API redesign must update the OpenSpec API section. |
| ASM-004 | accepted | Use Node.js `scrypt` with random salts for password hashing and opaque, hashed session tokens stored in PostgreSQL. | It provides a secure standard-library baseline without adding a native password dependency. | Password parameters and session expiry are configuration values. | Auth tests cover hash non-reversibility, login, expiry, and revocation. |
| ASM-005 | accepted | Keep domain/application tests runnable with in-memory ports; use PostgreSQL and Compose only for integration verification. | Docker is unavailable during the normal development phase. | In-memory adapters must preserve the same invariants as persistent adapters. | PostgreSQL migration and Compose tests are final-phase gates; persistence contract tests run against both ports. |
| ASM-006 | accepted | Run retention cleanup from the worker loop and expose an explicit cleanup operation; do not add a separate scheduler service. | The cleanup scheduler and storage placement were left open and a single worker is already required. | Cleanup is best-effort and observable through worker status/logs. | Test age/size limits and preservation of desired/applied state and active certificates. |
| ASM-007 | accepted | The control helper is the only component allowed to use a deployment control mechanism; worker requests a fixed allowlisted operation over a private Unix socket. | This resolves the worker/helper ambiguity in favor of the least-privileged boundary. | Compose may grant the helper the minimum control capability; web and worker receive no Docker socket. | Protocol tests reject unknown operations and user-supplied commands; Compose inspection verifies mounts. Promote to a decision if the boundary changes. |
| ASM-008 | accepted | Implement CoreDNS and Nginx renderers as pure deterministic functions, with service execution behind ports. | Rendering must be testable without services and secrets must not leak into candidates. | Candidate files and checksums are stable fixtures. | Golden/fixture tests and final `coredns`/`nginx -t` verification. |
| ASM-009 | accepted | Implement real ACME/Cloudflare adapters behind interfaces and fake deterministic adapters for TDD; no live credentials are stored in the repository. | The user confirmed both adapter types while no credentials/domains were supplied. | Live issuance is environment-dependent and may remain unverified. | Fake adapter tests run normally; live staging tests run only with supplied secrets in the final phase. |
| ASM-010 | accepted | Generate self-signed certificates with a pure TypeScript-compatible library and store private keys encrypted through the shared secret service. | Node's standard library does not provide a convenient X.509 certificate builder. | The certificate package is isolated behind a small certificate port. | Certificate parsing and TLS fixture tests; replace the library without changing the port. |
| ASM-011 | accepted | Treat the Next.js UI as a functional administration surface, not a pixel-identical design deliverable. | The docs define journeys and fields, not visual specifications. | All MVP actions are reachable with accessible forms/tables/status views. | Route/component tests and manual journey checks; visual redesign remains additive. |
| ASM-012 | accepted | Use environment variables for database URL, master key, session policy, ingress defaults, and external provider credentials. | Deployment secrets must remain outside source control. | Missing required secrets fail closed at startup or at the operation boundary. | Startup/config tests and Compose `.env.example`; never commit real values. |
| ASM-013 | accepted | HTTP-01 challenge serving is represented by the certificate/job boundary and a controlled challenge artifact; Nginx integration is validated in Compose. | The docs require issuance but do not define a separate challenge entity or route API. | The worker owns challenge lifecycle and cleanup. | Fake ACME tests cover lifecycle; final staging test validates reachability. |
| ASM-014 | review | Use the documented Nginx image tag and make the deployment digest configurable until the official digest is confirmed. | The docs require a digest-pinned image but do not include the digest. | A production-like deployment must resolve and freeze the digest before release. | Final Docker verification records the resolved digest or promotes a new decision. |
| ASM-015 | accepted | Keep the repository's required Node/pnpm versions in `package.json` and container images, while allowing the current local Node 24.14.1/pnpm 11.16.0 to run compatibility checks where possible. | The host Node toolchain differs from DEC-022 and cannot be changed implicitly. | A strict production build may require Node 24.19/pnpm 11.16. | Typecheck/test results state the actual toolchain; container verification is the authoritative pinned-toolchain gate. |
| ASM-016 | accepted | Treat CoreDNS promotion as a fixed control-helper operation: write the Corefile through Docker's archive API, synchronize zone files through a control-only shared volume, and restart CoreDNS to load changed zone contents. | The official CoreDNS image is minimal and non-root, so in-container `cp`, `rm`, and signal commands are unavailable or unauthorized; a reload-only signal also does not reliably reload changed zone files. | The control helper retains the only Docker socket and CoreDNS has a short controlled restart during apply. | Compose verification exercises managed/forwarded queries plus apply and rollback; replace with a zero-downtime data-plane mechanism if required later. |

## Explicit non-assumptions

- No real Cloudflare token, ACME account key, domain, private key, or production
  endpoint is invented.
- No deferred product capability is silently implemented as an MVP requirement.
- No raw user input becomes a shell command, CoreDNS directive, or arbitrary
  Nginx directive.
